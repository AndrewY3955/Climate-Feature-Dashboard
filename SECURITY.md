# Security policy

## Reporting a vulnerability

Please do not report security vulnerabilities in public GitHub issues, discussions, or pull requests. Public reports can expose users to risk before a fix is available.

Use GitHub's **Report a vulnerability** option on the repository Security tab to submit a private vulnerability report. The repository owner must enable **Private vulnerability reporting** in the repository's Settings under **Code security and analysis** for this option to be available.

If private reporting is unavailable, contact the repository owner privately through their GitHub profile. Do not post exploit details, credentials, tokens, private data, or proof-of-concept payloads in a public issue.

## Safe bug reports

For ordinary bugs, use the public bug-report issue form. Include only the minimum information needed to reproduce the problem. Use synthetic or public example data and redact usernames, personal paths, access tokens, credentials, and private source material from logs.

## Scope and limitations

This is a classroom proof-of-concept project. The local dashboard is not designed to receive confidential data or to serve as a production security boundary. Do not upload sensitive datasets or secrets to the repository.
